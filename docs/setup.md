# Настройка окружения

> Сделайте это **до первого семинара**. На паре мы потратим на проверку 5–10 минут,
> а не полчаса на установку.

## 1. Установить Go

Официальные сборки — на <https://go.dev/dl/>. Ставьте **последнюю стабильную версию**.

| ОС | Как поставить |
|---|---|
| macOS | Скачать `.pkg` с go.dev/dl и запустить. Либо `brew install go` |
| Windows | Скачать `.msi` с go.dev/dl и запустить |
| Linux | Скачать `.tar.gz`, распаковать в `/usr/local`, добавить `/usr/local/go/bin` в `PATH` |

Для Linux по шагам:

```bash
sudo rm -rf /usr/local/go
sudo tar -C /usr/local -xzf go1.XX.X.linux-amd64.tar.gz
echo 'export PATH=$PATH:/usr/local/go/bin' >> ~/.bashrc
source ~/.bashrc
```

> **Не ставьте Go из apt/yum**, если там лежит старая версия: в дистрибутивах Go
> часто отстаёт на несколько релизов, а нам нужны свежие возможности языка.

## 2. Проверить, что всё работает

```bash
go version
```

Должно напечатать что-то вроде `go version go1.26.5 darwin/arm64`.
Если команда не найдена — Go не в `PATH`, перезапустите терминал.

```bash
go env GOROOT GOPATH GOMODCACHE
```

- `GOROOT` — куда установлен сам Go. Трогать не нужно.
- `GOPATH` — рабочая папка Go (по умолчанию `~/go`). Скачанные зависимости
  и бинарники `go install` лежат там. **Ваш проект больше НЕ обязан лежать внутри
  GOPATH** — так было до Go 1.11, во всех старых учебниках. Сейчас есть модули.

## 3. Редактор

Выберите одно:

- **VS Code** + расширение **Go** (издатель Go Team at Google, идентификатор `golang.go`).
  После установки расширение само предложит доустановить `gopls` — соглашайтесь.
  Это языковой сервер: автодополнение, переход к определению, подсветка ошибок.
- **GoLand** от JetBrains. Для студентов бесплатно по образовательной лицензии.

Обязательно включите **форматирование при сохранении** — в Go это не вопрос вкуса
(см. `gofmt` ниже).

## 4. Забрать репозиторий с материалами

```bash
git clone git@github.com:DanielShinoda/ami_go_seminars_26.git
cd ami_go_seminars_26
make doctor
```

`make doctor` печатает версию Go и прогоняет тестовый пример. Если в конце
написано «Окружение готово» — всё настроено.

Если `make` у вас нет (обычно это Windows без установленного make), та же
проверка напрямую:

```bash
go version
go test ./seminar-01-intro/examples/05-first-test
```

## Проверочный список

- [ ] `go version` печатает версию
- [ ] Редактор подсвечивает ошибки в `.go`-файлах
- [ ] Файл переформатируется при сохранении
- [ ] `make doctor` печатает «Окружение готово»

## Если что-то не работает

| Симптом | Причина и что делать |
|---|---|
| `go: command not found` | Go не в `PATH`. Перезапустите терминал; проверьте, что путь к `go/bin` добавлен в профиль оболочки |
| `go.mod file not found` | Вы запускаете команду вне папки репозитория. Перейдите в корень `ami_go_seminars_26` |
| Редактор не подсвечивает ошибки | Не установлен `gopls`. В VS Code: палитра команд → `Go: Install/Update Tools` → выбрать все |
| `cannot find module providing package` | Опечатка в пути импорта либо вы не в модуле |

Если ничего не помогло — **не тратьте на это час**. Напишите преподавателю
с текстом ошибки и выводом `go version` и `go env`.
