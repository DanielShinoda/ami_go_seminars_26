## 1. Разбор прошлых задач (00:00–00:10)

На что смотреть в решениях группы:

- **`SumTo` формулой вместо цикла** — в условии просили цикл; заодно повод
  показать `for i := range n`.
- **`MinMax` со стартовым значением `0`** — классическая ошибка: на слайсе
  из одних отрицательных чисел максимум окажется нулём. Правильно —
  стартовать с `nums[0]`, предварительно проверив длину.
- **`RoundToInt` через `int(c + 0.5)`** — работает для положительных
  и врёт для отрицательных. Правильный ответ — `int(math.Round(c))`.
- **Не запущенный `gofmt`** — напомнить про форматирование при сохранении.

## 2. Переменные и константы (00:10–00:25)

[`examples/01-vars-consts`](examples/01-vars-consts/main.go)

Три формы объявления, и все три нужны:

```go
var attempts int = 0   // полная: когда тип важнее значения
var host = "localhost" // тип выводится из значения
port := 8080           // короткая форма — ТОЛЬКО внутри функции
```

На уровне пакета `:=` не работает: там только `var` и `const`.
Внутри функций в реальном коде почти всегда пишут `:=`, а `var` оставляют
для случая «нужно нулевое значение»:

```go
var buf strings.Builder   // нужен нулевой Builder, значения ещё нет
```

**Нулевые значения.** Каждая переменная инициализируется автоматически:
`0` для чисел, `false` для `bool`, `""` для строк, `nil` для указателей,
слайсов, мап, каналов и функций. Неинициализированной памяти в Go не бывает —
в отличие от C++, где это неопределённое поведение.

**Множественное присваивание** — обмен без временной переменной:

```go
a, b = b, a
```

Правая часть вычисляется целиком **до** присваивания — поэтому это работает.

**Пустой идентификатор `_`** — «значение мне не нужно». Единственный способ
законно проигнорировать результат, не нарушив правило «объявил — используй».

```go
_, err := doSomething()
```

**Константы** вычисляются на этапе компиляции, у них нет адреса.

```go
const MaxRetries = 3
```

**`iota`** — счётчик внутри блока `const`, штатная замена отсутствующему `enum`:

```go
type Weekday int

const (
	Monday Weekday = iota // 0
	Tuesday               // 1 — выражение справа повторяется само
	Wednesday             // 2
)
```

> **Углублённо: нетипизированные константы.** `const x = 1` не имеет типа
> до момента использования, поэтому `var f float64 = x` работает,
> хотя `var i int = 1; var f float64 = i` — ошибка. Константы в Go — это
> математические значения произвольной точности, а тип они получают
> только там, где нужны. Отсюда и `1 << 62`, которое не переполняется
> на этапе компиляции.

## 3. Типы, строки и руны (00:25–00:40)

[`examples/02-strings-runes`](examples/02-strings-runes/main.go)

**Числовые типы:** `int`, `int8/16/32/64`, `uint...`, `float32/64`,
`byte` (= `uint8`), `rune` (= `int32`). По умолчанию берите `int`
и `float64` — фиксированный размер нужен, когда важен формат данных
(сеть, файлы, экономия памяти).

**Все преобразования явные:**

```go
count := 7
ratio := float64(count) / 2
```

Даже `int32` → `int64` пишется руками. Раздражает пять минут, зато
исчезают все ошибки сужения типа, знакомые по C++.

### Строки: главная ловушка курса

Строка в Go — **неизменяемая последовательность байтов в UTF-8**.
Не массив символов, как хочется думать после Python.

```go
s := "Привет"
len(s)            // 12 — БАЙТОВ, а не символов! Кириллица занимает 2 байта
len([]rune(s))    // 6  — вот столько символов
s[0]              // 208 — это байт (тип byte), а не буква "П"
s[0] = 'X'        // не компилируется: строки неизменяемы
```

Правильный обход по символам — `range`, который декодирует UTF-8:

```go
for i, r := range "Го!" {
	// i — индекс НАЧАЛА руны в байтах: 0, 2, 4 (он "прыгает")
	// r — руна (тип rune), код символа Unicode
}
```

Чтобы изменить строку — переводим в `[]rune`, правим, собираем обратно:

```go
r := []rune(s)
r[0] = 'п'
s = string(r)
```

**Склейка в цикле.** `s += x` создаёт новую строку на каждой итерации —
это `O(n²)` по памяти. Для сборки используйте `strings.Builder`.

> **Углублённо: три представления одного текста.**
> `string` — неизменяемые байты. `[]byte` — изменяемые байты, сюда переводят
> для работы с вводом-выводом. `[]rune` — коды символов, сюда переводят
> для посимвольной обработки. Преобразования `[]byte(s)` и `[]rune(s)`
> **копируют данные** — это не бесплатная операция, и в горячем цикле
> так делать не стоит.

## 4. Управляющие конструкции (00:40–01:00)

[`examples/03-control-flow`](examples/03-control-flow/main.go)

Их всего три. **Нет** `while`, `do-while` и тернарного оператора `?:`.

### `if`

Скобок вокруг условия нет, фигурные скобки обязательны всегда —
даже для одной строки.

```go
if x > 5 {
	...
} else if x == 5 {
	...
}
```

**`if` с инициализатором** — основная идиома Go. Переменная видна только
внутри `if`/`else`, дальше её не существует:

```go
if v, err := parse(s); err != nil {
	return err
} else {
	fmt.Println(v)
}
```

Так область видимости сужается до минимума, и переменная не «протекает»
в остальную функцию.

### `for` — единственный цикл, в пяти формах

```go
for i := 0; i < 3; i++ { }     // 1. как в C++
for n > 0 { }                  // 2. как while
for { }                        // 3. бесконечный, выход по break
for i := range 3 { }           // 4. range по числу: i = 0,1,2 (Go 1.22+)
for i, v := range nums { }     // 5. range по коллекции
```

**Ловушка `range`:** `v` — это **копия** элемента. Изменение `v` не меняет
коллекцию:

```go
for _, v := range nums { v *= 2 }   // nums НЕ изменился
for i := range nums { nums[i] *= 2 } // а вот так изменился
```

`break` и `continue` работают как обычно; с **меткой** они управляют внешним
циклом — это замена отсутствующему `goto` из вложенных циклов:

```go
outer:
	for i := range 3 {
		for j := range 3 {
			if j > i { continue outer }
		}
	}
```

> **Углублённо: переменная цикла.** До Go 1.22 переменная цикла была одна
> на все итерации, и захват её замыканием давал печально известный баг —
> все горутины видели последнее значение. С Go 1.22 переменная **своя
> на каждой итерации**, и проблема исчезла. Если увидите в старых статьях
> совет `i := i` в начале тела цикла — это лечение именно этой болезни;
> сейчас оно не нужно.

### `switch`

```go
switch day {
case 1, 2, 3, 4, 5:   // несколько значений в одном case
	fmt.Println("будни")
case 6, 7:
	fmt.Println("выходные")
default:
	fmt.Println("нет такого дня")
}
```

**`break` в конце `case` не нужен** — проваливания нет, это ровно наоборот
по сравнению с C++. Провалиться явно можно через `fallthrough`, но нужно
это редко.

**`switch` без выражения** = лестница `if/else if`, только читается лучше:

```go
switch {
case score >= 90:
	return "отлично"
case score >= 75:
	return "хорошо"
default:
	return "неудовлетворительно"
}
```

Это же — стандартная замена отсутствующему тернарному оператору,
когда веток больше двух.

## 5. Функции (01:00–01:20)

[`examples/04-functions`](examples/04-functions/main.go)

```go
func divmod(a, b int) (int, int) {   // параметры одного типа — через запятую
	return a / b, a % b
}
```

**Множественный возврат** — не трюк, а идиома. В C++ для этого нужны
выходные параметры по ссылке или `std::pair`; в Go это встроено в язык.
Второе значение по соглашению — ошибка:

```go
v, err := parsePositive("42")
if err != nil {
	return err
}
```

Ошибка в Go — это **значение**, а не исключение. Её нельзя «не заметить»:
компилятор заставит либо использовать переменную, либо явно выбросить её
в `_`. Подробно — на семинаре про ошибки.

**Именованные результаты** документируют, что есть что:

```go
func split(sum int) (x, y int) {
	x = sum * 4 / 9
	y = sum - x
	return   // "голый" return вернёт текущие x и y
}
```

Голым `return` злоупотреблять не стоит: в длинной функции непонятно,
что именно возвращается.

**Переменное число аргументов:**

```go
func Sum(nums ...int) int { ... }   // внутри nums — обычный []int

Sum(1, 2, 3)
Sum(nums...)   // "раскрыть" слайс в аргументы
```

**Функция — это значение.** Её можно положить в переменную, передать
аргументом, вернуть из другой функции:

```go
func applyAll(nums []int, f func(int) int) []int { ... }

applyAll(nums, func(x int) int { return x * x })
```

**Замыкание** — функция, захватившая переменные окружения:

```go
func counter() func() int {
	n := 0
	return func() int {
		n++
		return n
	}
}

next := counter()
next() // 1
next() // 2
```

`n` живёт столько же, сколько возвращённая функция. Компилятор сам решает,
разместить её на стеке или в куче — это называется escape-анализ, и
беспокоиться об этом не нужно.

### `defer`

[`examples/05-defer`](examples/05-defer/main.go)

`defer` откладывает вызов до **выхода из функции** (не из блока!).
Для тех, кто из C++, — это явный RAII; для тех, кто из Python, — `with`/`finally`.

```go
f, err := os.Open(name)
if err != nil {
	return err
}
defer f.Close()   // закрытие пишем сразу рядом с открытием
```

Смысл — держать освобождение ресурса рядом с его захватом. Читателю не нужно
проверять, закрыт ли файл на всех восьми ветках `return`.

Отложенные вызовы складываются в стек и выполняются **в обратном порядке**
(LIFO), в том числе при панике.

**Ловушка 1: аргументы вычисляются сразу, в момент объявления `defer`.**

```go
i := 0
defer fmt.Println(i)   // напечатает 0, а не 10
i = 10
```

**Ловушка 2 (она же приём): `defer` может изменить именованный результат.**

```go
func namedResult() (result int) {
	defer func() { result *= 2 }()
	return 21   // вернётся 42
}
```

Это единственный способ поправить возвращаемое значение перед выходом —
на нём же построена обработка паник через `recover`.
